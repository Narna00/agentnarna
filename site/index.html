01 / the method

Adaptive, not noisy.

Human-style testing is not endless payload mutation. It is forming a precise hypothesis, measuring the control, changing strategy, and stopping when evidence answers the question.

A / MAP

Model the workflow

Prioritize business actions, identities, state changes, and sibling surfaces instead of dumping every URL into the model.

B / ADAPT

Learn from controls

A 403, sanitizer, or WAF becomes a fingerprint. The next attempt must test a different parsing, identity, route, or workflow assumption.

C / VERIFY

Demand an oracle

Reflection, errors, delays, and scanner labels are observations. A reproducible cross-identity read, browser execution, data access, or safe canary is proof.

02 / proof spine

Findings are a state transition.

The dashboard keeps leads and suppressed candidates visible without inflating the finding count. Only verified evidence reaches the report writer.

STATE 01

Lead

An anomaly or attack-surface signal. Worth a test, not a claim.

STATE 02

Candidate

A concrete hypothesis with an endpoint, input, sink, and expected oracle.

STATE 03

Verified finding

A fresh deterministic verifier reproduces real impact and links exact proof.

STATE 04

Reportable

In scope, non-duplicate, program-eligible, reproducible, and human reviewed.

03 / live technique intel

External research is stored as concise, source-linked hypotheses. Popularity never substitutes for target-specific proof.
